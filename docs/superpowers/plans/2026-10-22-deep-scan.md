# Deep Scan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One fruit, one guided ~5s multi-angle capture → locally-deterministic frame selection → one composite image → one Clef-gated call to the real `/api/v1/deep-scan` → Gemini verdict / "not enough angles + manual touch-checks", fully localized en-GB + pt-BR — delivered as ONE real implementation, with the house `mock-api-client` parity kept for offline/dev exactly as the existing scan path does.

**Architecture:** Single real stack, built by reusing GDP-grade existing infrastructure end-to-end: contract schema lane, prompt registry, verify/repair cycle, Clef gate, adapter/gateway plumbing, i18n copy gates, scan state machine, image pipeline, telemetry, and the `api-client`/`mock-api-client` twin pattern. New dedicated Worker endpoint `/api/v1/deep-scan` with a 2-question Clef gate mode, `deep_scan_v1` prompt version, and a deep-scan verifier lane. Deep Scan never feeds round 1–3 ranking and charges no quota in MVP.

**Tech Stack:** React 19 + Vite PWA (`apps/web`), Hono on Cloudflare Workers (`apps/proxy`), Zod contract (`packages/contract`), Vercel AI SDK + `@ai-sdk/google`, Workers AI Clef gate, vitest + Playwright + live-runner evals (`packages/evals`).

**Spec:** `docs/superpowers/specs/2026-10-22-deep-scan-design.md`

## Global Constraints

- **This plan ships the real stack end-to-end in one branch** — the mock twin is delivered as the repo does today (same `ApiClient` interface, offline/dev parity), not as a demo stage replacing the real path.
- No network and no AI during the capture window; selection/composite are deterministic pure functions of captured frames (spec §2).
- Composite ≤ ~250KB, tiles 448×448 on a 2×3 grid (1344×896), numbered 1–6; bbox crop only, no oval masking.
- Deep-scan route body limit 1MB; round-scan `POST /api/v1/scan` stays byte-identical at 500KB.
- Quota: deep scan consumes nothing; only the existing gate-spend accounting is recorded; pricing entry stays a TODO comment.
- Every new user-visible key lands in `apps/web/src/i18n/locales/en.json` AND `pt-BR.json` in the same commit; copy-gate suite must pass.
- All free-text model output (evidence, manualChecks, message) must follow the request `locale`.
- Privacy identical to scan v1: gateway `skipCache: true, collectLog: false`, trace headers via `getGatewayTraceHeaders`, request-scoped images only.
- Production deploys happen only via `.github/workflows/deploy.yml` on main; no version bumps in feature tasks.
- Existing suites must stay green at every commit: `pnpm -C apps/web test`, `pnpm -C packages/evals test`.

## Review Focus

1. **pt-BR `locale` request but English model output** — the outcome card and manualChecks must render Portuguese; pinned by the deep-scan live eval pt-BR arm (Task 10) and prompt-locale test (Task 4).
2. **Empty-oval composite (no produce anywhere)** — must be denied by the Clef gate before any Gemini spend; pinned by gate deep-scan tests (Task 5) and gate eval fixtures (Task 10).
3. **All-blurry or all-dark batch** — must die locally with an instant deterministic message, never reach the network; pinned by selector tests (Task 2).
4. **manualChecks leaking onto a confident verdict** — verifier must strip/forbid them when confident; pinned by verifier tests (Task 6).
5. **Oversized/oversampled request (>1MB body, >30 samples)** — must fail fast with a clean client-facing `analysis_failed`-style response, no partial state; pinned by endpoint tests (Task 7).

export interface FrameSample {
  sequence: number;                                   // 0..N capture order
  gray: Float32Array;                                 // tapped grayscale, w*h length
  grayW: number; grayH: number;
  thumb: Float32Array;                                // exactly 32*32
}
export interface DeepScanSelectionParams {
  max: number;              // 6
  weights: { sharpness: number; exposure: number; spread: number };  // {0.5, 0.2, 0.3}
  similarityLow: number;    // 4   (mean abs diff 0..100; below => near-duplicate)
  similarityHigh: number;   // 45  (above => suspicious jump, penalized)
  blurRejectQuantile: number; // 0.2 (bottom-sharpness band rejected outright)
}
export function sharpnessScore(gray: Float32Array, w: number, h: number): number   // 0..1 edge energy
export function exposureScore(gray: Float32Array): number                         // 0..1
export function similarityScore(a: Float32Array, b: Float32Array): number          // mean abs diff 0..100
export function selectFrames(samples: FrameSample[], params: DeepScanSelectionParams): { kept: FrameSample[]; stats: { sampled: number; rejectedBlur: number; rejectedExposure: number; rejectedSimilarity: number } }

**Verifier rules (every one pinned by a test):**
- Re-validate via `DeepScanResponseModelSchema`.
- `status ok` ⇔ `evidence.length ≥ 1` ∧ `quality.sufficientVisualEvidence === true` ∧ `ripeness.state !== "unknown"`.
- Confident verdict (`ok ∧ sufficientVisualEvidence ∧ confidence ≥ 0.8`) must carry `manualChecks == null`; if the model padded them, STRIP and record a repair error instead of failing.

- `ripeness.state "unknown"` requires `abstentionReason` + `message` naming what's missing AND requesting a useful new view.
- Behavior style: repair loops only; never throw on nested validation — errors array, like the round-scan verifier.
